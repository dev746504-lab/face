# Web Migration Design

## Goal
Replace the PyQt desktop interface with a local Flask web dashboard for one attendance computer with one browser camera, while preserving the existing dataset, DeepFace recognition, and Google Sheets attendance flow.

## Architecture
- `web_app.py` serves the dashboard and JSON endpoints.
- Browser JavaScript owns camera access through `getUserMedia` and sends JPEG frames to Flask.
- Flask performs DeepFace extraction/search, dataset writes, model training, and Google Sheets updates.
- Existing desktop scripts remain unchanged for fallback and comparison.

## Endpoints
- `GET /`: dashboard.
- `POST /api/recognize`: recognize one submitted camera frame and mark attendance once per browser session/day.
- `POST /api/capture`: extract and save one face image for a named person and capture stage.
- `POST /api/upload`: extract faces from uploaded images into a named dataset folder.
- `POST /api/train`: run the existing training script and return its output.
- `GET /api/health`: verify the app process and dataset availability.

## UI
The dashboard has three focused areas: live attendance camera, guided dataset capture, and admin actions for upload/train. Status messages are visible and actionable; camera permission and backend errors are reported without crashing the page.

## Recognition behavior
The web flow continues using DeepFace with the existing `dataset` directory. `face_model.yml` and `labels.json` remain generated by the existing training script but are not used by the DeepFace recognition path.

## Validation
Validate Python syntax, Flask route responses without a camera, browser page loading, and graceful errors when `credentials.json` or a camera is unavailable. Full recognition validation requires a configured Google service account and camera.

## Deployment (Render)
- `render.yaml` defines a single web service running `gunicorn web_app:app` with one worker (TensorFlow/DeepFace load per process, so extra workers multiply memory).
- `requirements-web.txt` is the deploy dependency set: same as `requirements.txt` minus PyQt6 (desktop-only) and with `opencv-python-headless` instead of `opencv-python`/`opencv-contrib-python` (no GUI libs available in the container).
- Use at least Render's Standard plan (2GB RAM) — TensorFlow plus DeepFace's models need more than the Free/Starter tier's 512MB.
- Google Sheets credentials are passed via the `GOOGLE_CREDENTIALS_JSON` env var (paste the full service account JSON as the value in the Render dashboard) instead of committing `credentials.json`. `web_app.py` reads the env var first and falls back to a local `credentials.json` file for desktop/dev use.
- The `dataset/` directory is not on a persistent disk, so captured/uploaded face images and any trained artifacts are lost on redeploy or when the instance is recreated — re-upload and retrain after each deploy that needs a populated dataset.
- DeepFace downloads its model weights (ArcFace, RetinaFace) to the container's home directory on first use; the first recognize/capture/upload request after a deploy will be slower while weights download.
- Camera access (`getUserMedia`) requires HTTPS, which Render provides by default on its `onrender.com` subdomain and custom domains.
